# Vercel 배포 가이드

이 문서는 **처음 배포할 때 화면에서 무엇을 누르면 되는지**만 순서대로 적은 것입니다.
전체 소요 시간은 10분 안쪽입니다.

준비물은 GitHub 계정(이 저장소의 소유자)과 Vercel 계정 하나뿐입니다.
Vercel은 Google 계정으로 로그인해도 되고, GitHub 저장소 연결은 로그인 방식과 무관하게
별도로 GitHub 권한을 한 번 승인하는 절차를 거칩니다.

---

## 0. 먼저 확인할 것 — 기본 브랜치

Vercel은 **저장소의 기본(default) 브랜치**를 프로덕션으로 배포합니다.
이 저장소는 처음에 커밋이 없는 상태였기 때문에 작업 브랜치가 기본 브랜치로 잡혀 있습니다.

배포 전에 GitHub에서:

1. 저장소 → **Settings** → **General** → **Default branch**
2. 연필 아이콘을 눌러 **`main`** 으로 변경 → **Update**

그리고 PR을 `main` 에 머지해 두세요. 그래야 프로덕션이 `main` 을 따라갑니다.

> 순서를 반대로 해도 됩니다 — PR을 먼저 머지하고 기본 브랜치를 바꿔도 결과는 같습니다.

---

## 1. Vercel에 프로젝트 가져오기

1. <https://vercel.com/new> 로 이동합니다.
2. **Import Git Repository** 에서 `millionjang-hue/newzenai` 를 찾아 **Import** 를 누릅니다.
   - 목록에 없으면 **Adjust GitHub App Permissions** 를 눌러 이 저장소에 접근 권한을 줍니다.
3. 설정 화면이 뜨면 그대로 둡니다. Framework Preset이 **Next.js** 로 자동 인식되고,
   Build Command·Output Directory는 건드릴 필요가 없습니다.
4. 이 시점에는 **Deploy 를 눌러도 되고 안 눌러도 됩니다.** 눌렀다면 첫 배포는
   "데이터베이스 설정이 필요합니다" 안내 화면이 뜹니다 — 정상입니다. 다음 단계에서 해결됩니다.

---

## 2. 데이터베이스 연결 (Neon)

Vercel 프로젝트 안에서 바로 만들 수 있습니다.

1. 프로젝트 → **Storage** 탭 → **Create Database**
2. **Neon** (Serverless Postgres) 선택 → 리전을 고르고 생성합니다.
   무료 플랜으로 충분합니다.
3. 생성이 끝나면 **Connect Project** 에서 이 프로젝트와 **Production / Preview / Development**
   환경을 모두 선택해 연결합니다.

연동이 `DATABASE_URL` 을 자동으로 주입합니다. 접속 문자열을 직접 복사해 붙여넣을 필요가 없고,
서버리스에 적합한 **풀링된(pooled) 엔드포인트**가 사용됩니다.

> 다른 곳(Supabase, RDS 등)에서 만든 데이터베이스를 쓰려면 이 단계 대신
> Settings → Environment Variables 에서 `DATABASE_URL` 을 직접 추가하세요.
> 서버리스에서는 반드시 풀링된(pooler) 접속 문자열을 쓰고 `?sslmode=require` 를 포함시키세요.

---

## 3. 환경 변수 확인

Settings → **Environment Variables** 에서 다음을 확인합니다.

| 이름 | 값 | 필수 |
|---|---|---|
| `DATABASE_URL` | 2단계에서 자동 주입됨 | ✅ |
| `CRM_AUTO_SEED` | 데모 데이터를 넣으려면 `1` 또는 생략, 빈 상태로 시작하려면 `0` | 선택 |

실서비스로 쓸 계획이라면 `CRM_AUTO_SEED=0` 으로 두고 실제 데이터를 넣으세요.
지금은 화면을 확인하는 것이 목적이므로 그냥 두시면 됩니다(기본값이 시드 생성).

---

## 4. 배포

**Deployments** 탭 → 최신 배포의 **⋯** → **Redeploy** 를 누릅니다.
(2단계에서 환경 변수가 추가됐기 때문에 한 번 다시 배포해야 반영됩니다.)

배포가 끝나고 URL을 열면:

- 테이블이 없으면 **첫 요청 때 스키마를 만들고** 데모 데이터를 채웁니다(1초 안팎).
- 그래서 첫 페이지 로딩만 조금 느리고, 이후로는 정상 속도입니다.
- 인스턴스가 여러 개 동시에 떠도 Postgres 어드바이저리 락으로 직렬화되므로
  데이터가 중복 생성되지 않습니다.

---

## 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| "데이터베이스 설정이 필요합니다" 화면 | `DATABASE_URL` 이 없습니다. 2단계를 마친 뒤 **Redeploy** 하세요. |
| "화면을 불러오지 못했습니다" 화면 | 접속 문자열은 있지만 연결에 실패했습니다. 풀링된 엔드포인트인지, `?sslmode=require` 가 붙어 있는지 확인하세요. Vercel → Deployments → 해당 배포 → **Runtime Logs** 에 원인이 찍힙니다. |
| 배포는 되는데 예전 코드가 뜸 | 기본 브랜치가 `main` 이 아니거나 PR이 아직 머지되지 않았습니다. 0단계를 확인하세요. |
| 커넥션 수 초과 오류 | 풀링되지 않은 엔드포인트를 쓰고 있을 가능성이 큽니다. 그래도 남으면 `PGPOOL_MAX=1` 을 설정하세요. |

## 배포 이후

- **자동 배포**: 이제 `main` 에 푸시하면 자동으로 프로덕션에 반영되고, PR을 올리면
  프리뷰 배포 URL이 생깁니다.
- **데이터 초기화**: 로컬에서 프로덕션 `DATABASE_URL` 을 환경 변수로 주고
  `npm run db:reset` 을 실행하면 테이블을 드롭하고 다시 만듭니다.
  **프로덕션 데이터가 전부 지워지므로** 데모 단계에서만 쓰세요.
- **다음 작업**: 지금은 접속하면 누구나 전체 데이터를 볼 수 있습니다.
  사내에서 실제로 쓰려면 인증·권한이 먼저 필요합니다.
